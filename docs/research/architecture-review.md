# Architecture review: 24 design decisions checked against the docs

On 2026-11-24 every design decision in Model Router was checked against Claude Code 2.1.331 and the official Claude Code and Claude platform docs, fetched that day. The code checked was the code of that day: the 0.1.2 release and the unreleased changes after it, such as the marked redo that note 04 describes. There were 24 decisions, from the two routing paths to the docs site. Each got its own note: what the code did, what the sources say, quoted with their URLs, a verdict, the changes the sources back, and what they don't say. Each note is in [architecture/](architecture/), unchanged except for heading levels and a dated line under each title that says the note predates 0.3.0.

A second reader then checked each note: every cited page fetched again, every claim about the code read against the source, and every proposed change weighed on its own. That reading's record isn't in this repository, so the verdicts below are the notes' own. The notes describe the code as it stood before the redesign, so names in their "What we built" sections may no longer exist. The last column below says what the code does now, in 0.3.0, checked against the code and `git log main..HEAD`.

| Decision | Verdict | Why | What changed in the code | Note |
| :- | :- | :- | :- | :- |
| Two paths: the mod and the settings-hook fallback | Partly right | The mod is the only plugin path whose model outranks the caller's and the only one that reaches workflow agents, but a sticky per-session flag switched between the paths and missed a mod that stopped answering ([mods admin](https://code.claude.com/docs/en/plugins/mods/admin)) | The mod's `tool.call` hook marks each `Agent` call it routes under `mod-calls/`, and the fallback stands down only for a marked call (`mod.routes`). The session flag and `mod.json` are gone. The mod starts no Python on a main-loop turn (the `UserPromptSubmit` and `Stop` hooks still do), and `turn.step` only raises a workflow agent's effort | [01](architecture/01-two-paths.md) |
| Where a call's level comes from | Partly right | Keeping the model the caller or the agent's definition names matches the two choosers the docs name. English regex over the brief has no source behind it and sent legal and research work to Haiku ([sub-agents](https://code.claude.com/docs/en/sub-agents#choose-a-model)) | The brief scorer (`profile.py`), the routing and agent-name corpora and the agent-name rules are deleted. The session-start note gives Claude a table of model and effort by kind of work, and `router.decide` keeps what a call names within the cap. Bench tasks that aren't code: not changed yet | [02](architecture/02-level-signal.md) |
| The five-level ladder | Partly right | The rung order and the lookup, complex and frontier settings match the docs. Standard on Sonnet at `medium` and hardest at Opus `xhigh` are weaker, and `priority: quality` moved the model before the effort ([cost and intelligence](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)) | The rungs keep their models and efforts. Haiku's extra effort step stops at `high` (`effort_stops_at`). The `priority` option and the speed rank are gone, and a named model stands for its lowest rung (`ladder.rung`) | [03](architecture/03-ladder.md) |
| Redo escalation | Partly right | The shape is the documented one, but the trigger was Claude's judgment, the unmarked repeat fired on a deliberate re-run of a check, and the climb moved the model before the effort ([re-run failures](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence#re-run-failures-at-higher-effort)) | Only a call whose `description` starts with "Redo:" is a redo. One that names no `model` or `effort` climbs effort first, then model (`router._redo`); one that names either runs as named. The unmarked repeat, `calls.cut_off` and the stored description are gone. The route skill says to continue a run cut short with `SendMessage` | [04](architecture/04-redo-escalation.md) |
| The Stop gates | Partly right | Asking for a check before done is the docs' first lever. Both gates returned `decision: "block"` where the hooks reference names `additionalContext` for guidance, and the strong-agent gate fired on a wording estimate ([hooks](https://code.claude.com/docs/en/hooks#stop-decision-control)) | The Stop hook returns `additionalContext`, asks for the work's own check for any kind of work, makes no ask when the transcript can't be read, and waits for background shell and teammate tasks too. `strong_agent_gate` is deleted. `verify_gate` stays on by default | [05](architecture/05-stop-gates.md) |
| The learning loop | Wrong | No source describes a plugin changing its own routing from what it observes. Its votes were Claude's own choices, and the raise was machine-wide, silent and permanent, where Claude Code's own cross-session learning is visible and per repository ([memory](https://code.claude.com/docs/en/memory)) | `learn.py` and `learned.json` are deleted. `/model-router:usage` counts redos by the level they climbed from and says a level can be raised under `levels` in `~/.claude/model-router.json`. A raised level sets only the effort of a call that names a model and no effort, and the picks of a rule's `level`, a teammate's start and a redo's next model. Only a rule's `level` raises the model a call names | [06](architecture/06-learning-loop.md) |
| State files, locking and migration | Partly right | The data folder, atomic writes, the lock and the newer-file rule fit the docs, since an old release can keep writing the folder for 14 days after an update. The saved copy of the options, `locks.json` and a migration step that changed nothing serve nothing a source requires ([plugin loading](https://code.claude.com/docs/en/plugins/loading)) | Skills get the options as `${user_config.KEY}`, so `state.json` keeps no copy, and the migration table is deleted. Only `state.json` and `locks.json` carry a schema. Locks are OS locks on a `.flock` file. One file per session and dropping `locks.json`: not changed | [07](architecture/07-state-design.md) |
| Hook wiring | Partly right | Exec form, exact matchers and exits that never block follow the docs. The Stop block, a SubagentStop that ran for internal agents and Python starts that bought nothing did not ([hooks](https://code.claude.com/docs/en/hooks)) | The `Agent` hooks drop `Task`, SubagentStop matches `.`, and Stop returns `additionalContext`. The session's model is the newer of the recorded switch and the transcript (`session.model`). The async refresh hook and `mod-turn` are gone. A live run on native Windows: not done yet | [08](architecture/08-hook-wiring.md) |
| What the plugin puts in Claude's context | Partly right | SessionStart `additionalContext` is the right carrier, but notices meant for the user went through Claude, and the named-model note was false under `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` and above the cap ([hooks](https://code.claude.com/docs/en/hooks#json-output)) | The session note holds the level table and the redo rule as facts. The FORCE, `CLAUDE_CODE_SUBAGENT_MODEL` and workflow-model notices reach the user as `systemMessage` when a session opens. The named-model note is skipped under FORCE and says where the call runs. The hard-request note is gone | [09](architecture/09-context-notes.md) |
| The model registry and allowlists | Partly right | The alias rules match the docs, but the newest-version swap for a blocked alias holds only on the Anthropic API and Claude Platform on AWS, the settings-file reader couldn't see managed policy, and a lagging family ranked as its 5.5 model ([model config](https://code.claude.com/docs/en/model-config)) | The allowlist reads only the settings layers the mod sends. On the other providers a family counts only when the version its alias runs, or the newest ID the mod sends, is permitted. A host-managed or Mantle provider gets aliases only. The router's own picks move one family up from a lagging alias (`Registry.past_lag`). Sending the newest ID when the parent runs an older version: not changed | [10](architecture/10-model-registry.md) |
| Model health | Partly right | Claude Code's fallback chain already moves a subagent off an unavailable model, which leaves only a memory across turns. The detector parsed display text and locked a model out for up to 7 days ([model config](https://code.claude.com/docs/en/model-config#fallback-model-chains)) | A failure counts only when it carries an API error type (`health.MODEL_ERROR`). Two failures route a model around for one day, with no growth. A refused fallback rewrite strikes nothing. A model that isn't usable goes to the next stronger usable one (`Registry.clamp`) | [11](architecture/11-model-health.md) |
| Rule files and the trust model | Partly right | Options from `userConfig` and a cap no file can pass match the rule that a repository can't set plugin options. "A cloned repository can never run weaker" was false, and a file's `routing_mode` could turn down a managed value ([settings reference](https://code.claude.com/docs/en/settings-reference#pluginconfigs)) | `routing_mode` in either `model-router.json` is dropped and listed as a problem. The project file is the nearest `.claude/model-router.json` from `CLAUDE_PROJECT_DIR` (else the working directory) up to the repository root. A project's model and agent keys must be short plain names. The project file's `models` block and a rule's `model`: kept | [12](architecture/12-rule-files.md) |
| The role agents | Partly right | The files use only supported fields, but deep-solver added only a stronger model a call can name, docs-researcher overlapped a built-in agent, and floors read from agent names have no documented basis ([sub-agents](https://code.claude.com/docs/en/sub-agents)) | deep-solver and docs-researcher are deleted, leaving five agents. The architect and reviewer name `opus` at `high`, and the architect has no Bash. The agent-name rules are gone, and an eval grades which agent Claude picks. The scout stays, and the reviewer is still written for code | [13](architecture/13-role-agents.md) |
| Skills and commands | Partly right | Plugin skills with `disable-model-invocation` follow the docs, but the CLI read a saved copy of the options, and `ship` and `refresh` were outside routing ([skills](https://code.claude.com/docs/en/skills)) | Skills pass the options as `${user_config.KEY}` flags. `models` and `usage` drop `--json`, which the CLI keeps. `ship` is now the repository's `.claude/skills/deliver`, and `refresh` is `.claude/skills/refresh`. The plugin ships `route`, `models` and `usage` | [14](architecture/14-skills-commands.md) |
| The upstream watch | Partly right | A daily CI check matches the deprecations page's advice, but the fetch on users' machines fed nothing routing reads and ran where Claude Code's own background traffic doesn't ([model deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations)) | The plugin makes no network call. The refresh hook, `update_check`, `upstream.json`, the Models API call and the manifest's `network` field are gone. `tools/upstream_check.py` runs in CI, reads the changelog page and hashes each watched page's full text | [15](architecture/15-upstream-watch.md) |
| Workflow stages, ultracode and teams | Partly right | Routing stages and teammates through `agent.spawn` fits the docs, but the router overwrote a script's stage effort, moved stages below the session's model on a regex score, and could keep a teammate on Haiku for its whole life ([workflows](https://code.claude.com/docs/en/workflows)) | `turn.step` only raises a workflow agent's effort. A stage that names no model stays on its parent's model, held to the cap. A teammate whose parent is weaker than Sonnet starts on Sonnet | [16](architecture/16-workflows-teams.md) |
| main_effort | Partly right | The cache guard followed the docs, but the trigger was a regex guess at the request, and Claude Code already has `ultrathink` and `/effort` ([model config](https://code.claude.com/docs/en/model-config)) | The option and its code are deleted. The router leaves the main loop's effort alone | [17](architecture/17-main-effort.md) |
| The usage ledger and reports | Partly right | The routing rows record decisions nothing else records. The dollar side was a second price table beside Claude Code's own estimate, and the stored description was never read ([costs](https://code.claude.com/docs/en/costs)) | Usage rows hold Claude Code's estimate for each subagent from `$.agent.list()`. The report says it is not the bill and when a session is on a subscription. Main-loop usage rows, `total_tokens` and the description are gone, and rows older than 30 days are dropped | [18](architecture/18-ledger-reports.md) |
| The benchmark method | Partly right | Fresh copies and deterministic checks match the sources, but Bash was denied in 78 of 90 pilot runs and 507 of the 1,280 table rows, five of eight classes are saturated, and the analysis has no pairing or power check ([plugin evals](https://code.claude.com/docs/en/plugin-evals)) | Not changed yet. The stored rows measured an older design, and on the six harder pilot tasks that older router cost more than no router. This release has not been benchmarked | [19](architecture/19-benchmark-method.md) |
| Packaging and versioning | Partly right | Every manifest field is documented and used as described, but `main` reused versions, and an install updates only when the version string changes ([plugin loading](https://code.claude.com/docs/en/plugins/loading)) | CI fails a plugin change whose version `main` has carried or a tag holds (`tools/plugin_version.py`), validates on 2.1.329, 2.1.331 and the latest release, and validates daily on the newest. The manifest has one short description and no `network` field. This release's version: not set yet | [20](architecture/20-packaging.md) |
| Security and privacy | Partly right | Never returning `allow` and copying every field into `updatedInput` match the docs, but a project file could lift the cap, and one repository's failures or redos changed routing in every project ([settings reference](https://code.claude.com/docs/en/settings-reference)) | No project file sets `routing_mode`. A failure on an exact ID the caller or the agent named strikes no family. The learned raise is deleted, and no description text is stored. The ledger keeps 30 days, the data folder is 0700 and the files 0600, and the launcher runs Python with `-I` | [21](architecture/21-security-privacy.md) |
| Work that isn't software | Wrong | The docs define a hard task by its stakes, whether it can be checked, how open-ended and how long it is, never by its field. The plugin read software words, and the verify gate asked for tests on a spreadsheet ([choosing a model](https://platform.claude.com/docs/en/about-claude/models/choosing-a-model)) | The session note's table picks the model by how checkable, high-stakes, open-ended and broad the work is. The Stop ask names a check for code, figures and documents and counts an edit to any project file. An eval case summarizes a contract. A reviewer for any saved result and bench tasks that aren't code: not changed yet | [22](architecture/22-any-work.md) |
| How the plugin is tested | Partly right | The documented checks are used, but the mod tests use a hand-built fake of the engine, nothing ran on a release newer than 2.1.330, and the corpora had no held-out set ([mods test](https://code.claude.com/docs/en/plugins/mods/test)) | `validate` runs on 2.1.331 and the latest release, a daily job validates and type-checks against the newest, and the eval also runs weekly. Evals cover a marked redo, a contract summary and a call that names no agent. The corpora went with the scorer. The `claude plugin test` kit, dropping `typecheck.sh` and a check of the hooks' stdin fields: not changed yet | [23](architecture/23-testing.md) |
| Docs, site and discovery files | Partly right | The citation file, the sitemap and the plugin README rules follow their specs, but the FAQ structured data, a robots file under a subpath, the IndexNow key and some structured-data fields served no reader ([marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference)) | The site drops the FAQPage JSON-LD, `robots.txt`, the IndexNow key, `lastmod`, `dateModified`, `downloadUrl` and `operatingSystem`. `llms.txt` links only readable text. The marketplace entry has no description of its own. The plugin README says what the plugin runs and keeps, and the redo diagram names the mark | [24](architecture/24-docs-surface.md) |
