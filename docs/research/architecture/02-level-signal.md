# Where a call's level comes from: regex over the brief, the caller, or the agent definition

2026-11-25: this note checks Model Router as it stood on 2026-11-24, before the 0.3.0 redesign. "What we built" describes that code, and some of what it names is gone or works differently now. What the code does now is in the [architecture review](../architecture-review.md).

Researched 2026-11-24 against Claude Code 2.1.331 (`claude --version`), with every page fetched the same day. Code read in the `redo-fixes` worktree. This builds on `docs/research/caller-levels-and-redo.md` (the mechanics: what fields exist, what a mod can override, the redo signal) and does not repeat it. This page is about the design choice.

## What we built

- `scripts/modelrouter/profile.py` `profile_call(tool_input, agent_type)` joins the call's `description` and `prompt` and runs `read()`, then `_call_level()`. `read()` is English regex: four `SIGNALS` word lists (risk, scope, load, ambiguity), change and reasoning verbs (`_CHANGE`, `_REASONING`, `_DECISION`), a defect rule (`_fixes_a_defect`), `_FRONTIER`, `_THOROUGH`, `_LOOKUP`, negation stripping (`_NEGATED`), and a non-English guess (`_not_english`).
- `_call_level()` turns the hit counts into one of five levels: lookup, standard, complex, hardest, frontier. A brief that fixes or hunts a defect is at least complex.
- `role()` reads the agent's name. The plugin's own architect, reviewer and deep-solver have a floor (`ROLES`). Any other agent whose name has a part matching `_HEAVY_NAME` gets a complex floor, and one matching `_LIGHT_NAME` gets a standard cap.
- `router.decide()` takes `rule.level or profile["level"]`, raises it to a project rule's floor and to `Facts.floor` (the user request's own regex level from `request.load().floor`, set in `spawn.facts()` for the strong role agents only), and `ladder.pick()` maps the level to a model and effort from `config/models.json` `levels`: lookup Haiku `medium`, standard Sonnet `medium`, complex Opus `high`, hardest Opus `xhigh`, frontier Fable `high`.
- A `model` named on the call wins (`source = "caller"`) and is clamped to the cap by `reg.clamp()`. No floor applies to it, and the router sets no effort for it, since `LEVEL_SOURCES` leaves out "caller". An agent's own `model` is kept while `agent_pins` is `respect`.
- `hooks.session_start` tells Claude: "Calls omit `effort` unless the user named one, and name `model` only when the user did or when what was read shows the task harder or easier than its brief." `skills/route/SKILL.md` says "You don't choose a model per call" and "The brief is what the model is chosen from".
- The same regex also scores the user's request (`profile_prompt`, called from `intake.py`), and `hooks.post_agent` uses the "risk" signal to decide whether to warn about a mid-run model swap.

## What the sources say

### Who chooses a subagent's model

The docs name two choosers in Claude Code: the agent definition and the calling model.

- "To choose its model yourself, set the `model` field in its definition", and the order is "1. The per-invocation `model` parameter, which Claude can pass when it starts the subagent ... 2. The `model` field in the subagent's definition, including `inherit` 3. The `CLAUDE_CODE_SUBAGENT_MODEL` environment variable 4. The main conversation's model". https://code.claude.com/docs/en/sub-agents#choose-a-model
- The Agent tool's own parameter text puts no limit on `model`: "Optional model override for this agent. Takes precedence over the agent definition's model frontmatter and the configured default subagent model." It does limit `effort`: "Set this ONLY when the user, or instructions such as CLAUDE.md or a skill, explicitly ask that this agent or delegated work run at a specific effort level, never on your own judgment; otherwise omit it and the agent runs at its usual effort." Source: the generated type file `plugins/model-router/.claude-plugin/types/claude-code-tools/index.d.ts` (the `Agent` input).
- The cost advice is a fixed mapping in the definition: "For simple subagent tasks, specify `model: haiku` in your subagent configuration" https://code.claude.com/docs/en/costs#choose-the-right-model, and "Set `model: haiku` in a subagent's definition if its work is simple, like collecting the files that import a module or checking links in the docs" https://code.claude.com/docs/en/best-practices#know-what-subagents-cost.
- Per-call choice is described as something the person asks for: "Ask Claude to use a smaller model for stages that don't need the strongest one when you describe the task" https://code.claude.com/docs/en/workflows#cost, and "Spawn 4 teammates to refactor these modules in parallel. Use Sonnet for each teammate" https://code.claude.com/docs/en/agent-teams#specify-teammates-and-models.
- Anthropic's own multiagent product splits the work the same way: a predefined agent "uses its own configuration: model, system prompt, tools, MCP servers, and skills", and the calling agent picks which agent to hand a task to: "Escalation: Consult a more capable agent or model for a subset of complex subtasks", "Specialization: Route to agents with domain-focused system prompts and tools". https://platform.claude.com/docs/en/managed-agents/multiagent-orchestration#what-to-delegate
- Anthropic's research system fixed the models by role (an Opus 4 lead with Sonnet 4 subagents) and steered the lead with written rules, because the lead's own judgment of effort was weak: "Agents struggle to judge appropriate effort for different tasks, so we embedded scaling rules in the prompts. Simple fact-finding requires just 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each, and complex research might use more than 10 subagents". https://www.anthropic.com/research/multi-agent-research-system (June 2025, earlier models)
- On deciding in the model versus in the harness: "With the actual code in front of it, Claude is usually better placed to make that call than a rule you wrote in advance", while "The deterministic kind is for when you want to make sure certain things *always* happen (or never happen), no matter what the model decides." A plain CLAUDE.md line is followed "nearly every time. But no matter how strongly you word it, whether Claude follows that line on a given turn is still Claude's call." https://code.claude.com/docs/en/best-practices#deterministic-and-non-deterministic-instructions
- A third-party classifier is a documented pattern, with a condition: "Routing works well for complex tasks where there are distinct categories that are better handled separately, and where classification can be handled accurately, either by an LLM or a more traditional classification model/algorithm", for example "Routing easy/common questions to smaller, cost-efficient models like Claude Haiku 4.5 and hard/unusual questions to more capable models". The same post: "you should consider adding complexity only when it demonstrably improves outcomes." https://www.anthropic.com/research/building-effective-agents
- On the cost of routing wrong: "misrouting leads to poor results ... Specialization works best when domains are clearly separable and routing decisions are unambiguous." https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them (linked from the multiagent page above)
- On setting effort per task: "Start with default effort levels for each model and tune as a general preference based on the type of work you do rather than task-by-task." https://claude.com/blog/claude-model-and-effort-level-in-claude-code (linked from https://code.claude.com/docs/en/model-config)
- On wording as a difficulty signal: "Phrases like `think step by step` or `be thorough` are ordinary prompt text rather than keywords. The main control for how hard Claude thinks is the effort level". https://code.claude.com/docs/en/best-practices#write-a-specific-prompt. `_THOROUGH` in `profile.py` lifts a lookup to standard on exactly such words.
- A native cap on a caller-named model exists, as a deny: "`Agent(model:opus)` | Agent calls that request the Opus model tier", with "A parameter the model omits is never matched" and "The value is compared against the literal input Claude sends". https://code.claude.com/docs/en/permissions#match-by-input-parameter (added in 2.1.178, https://code.claude.com/docs/en/changelog). No native floor is documented.

### Writing a delegation brief

- "Each subagent needs an objective, an output format, guidance on the tools and sources to use, and clear task boundaries. Without detailed task descriptions, agents duplicate work, leave gaps, or fail to find necessary information." https://www.anthropic.com/research/multi-agent-research-system
- "Claude composes a delegation message that summarizes the task, and the subagent works from there." A rule that must reach the subagent: "restate it in the prompt you give Claude when delegating." https://code.claude.com/docs/en/sub-agents#manage-subagent-context
- For a harness's subagent tool description: "state what a subagent adds to the cost of a session, say when delegation is worth it and when it isn't, and tell the model how to brief a subagent that it starts." https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#set-expectations-for-subagents
- "If you name the file, describe the symptom, and say what 'fixed' looks like up front, you usually save yourself a round of corrections later." https://code.claude.com/docs/en/best-practices#write-a-specific-prompt
- A delegation prompt measured no gain: Opus 5.5 with Haiku 5.5 subagents passed "68.8% and $3.35 USD with subagents and no added prompt; 67.9% and $3.27 USD with subagents and the prompt" (a 113-word delegation prompt). https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence (reference 29)
- No source says a brief should carry words for a router to read. The route skill's advice to "say what makes a piece hard (the security angle, the cross-service reach) in the brief itself" exists only to feed the regex.

### Model choice by kind of work, outside software

- The platform's matrix: Fable 5.2 for "multistep deep research, analysis carried through to a finished document, spreadsheet, or deck"; Opus 5.5 for "Complex agentic coding and enterprise work"; Sonnet 5.5 for "Code generation, data analysis, content creation"; Haiku 5.5 for "high-volume intelligent processing ... subagent tasks". "Most workloads start with Claude Opus 5.5." https://platform.claude.com/docs/en/about-claude/models/choosing-a-model#model-selection-matrix
- Legal: "Model accuracy is extremely important when summarizing legal documents. Claude Opus 5.5 is an excellent choice for use cases such as this where high accuracy is required. If the size and quantity of your documents are large such that costs start to become a concern, you can also try using a smaller model such as Claude Haiku 5.5." https://platform.claude.com/docs/en/about-claude/use-case-guides/legal-summarization#select-the-right-claude-model
- Classification: "Claude Haiku 5.5 ... at `low` effort it handles simple, high-volume requests such as classification. If your classification problem requires deep subject matter expertise ... you may opt for the larger Sonnet model." https://platform.claude.com/docs/en/about-claude/use-case-guides/ticket-routing#choose-the-right-claude-model
- Anthropic's model guide, by task: "Everyday documents, slides, and spreadsheets: Sonnet 5.5, high ... For a complex financial model, or a document built from a large pile of source material, start on Opus 5.5"; "Agent tasks you run repeatedly such as investigation, review, or drafting: Sonnet 5.5, medium"; "Deep research, and scientific or quantitative analysis: Fable 5.2"; "Subagents that search files, read logs, or summarize: Haiku 5.5 or Sonnet 5.5 ... Wrong answers are cheap to spot, and the main model has the judgment calls anyway." Also: "Keep small models on work where a mistake is cheap to spot ... Keep code edits and judgment calls on the main model." https://claude.dev/blog/which-claude-model-should-you-build-with/ (Anthropic's blog; not linked from the pages above)
- Research: on DeepResearch Bench II "Claude Opus 5.5 scored 2.4 points above Claude Sonnet 5.5 for 1.5 times the cost per task. Claude Fable 5.2 cost 4.3 times as much as Claude Sonnet 5.5 for no measurable gain in score". Effort matters there: "Claude Opus 5.5 scored 13.3 points lower at `low` than at `medium` on DRACO". https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence#compare-models-on-cost-per-task and #tune-effort
- The docs' own analysis example is a fixed mapping: a data-scientist subagent that "explicitly sets `model: sonnet` for more capable analysis". https://code.claude.com/docs/en/sub-agents (example subagents)

What the scorer does with such work. I ran `profile_call()` read-only on ten briefs with a `general-purpose` agent:

| Brief | Level today, and the model it maps to | What the sources point to |
| :- | :- | :- |
| "Summarize the indemnity and termination clauses in contracts/msa.pdf and flag anything unusual" | lookup, Haiku `medium` | Opus 5.5 for legal summaries where accuracy matters (legal guide) |
| "Prepare a memo on whether the client qualifies for the R&D tax credit, with citations" | lookup, Haiku | judgment work, kept on the main model (model guide) |
| "Survey the literature on GLP-1 drugs and muscle loss and weigh the evidence" | lookup, Haiku | deep research: Opus or Fable, and `low` effort costs 13.3 points on DRACO |
| "Build a discounted cash flow model ... with three scenarios" | standard, Sonnet `medium` | "a complex financial model ... start on Opus 5.5" |
| "Review this supplier agreement for liability exposure and recommend redlines" | standard, Sonnet `medium` | not documented for contracts; review is judgment work |
| "Write a 2,000 word essay" | standard, Sonnet `medium` | Sonnet 5.5 at `high` for documents (model guide) |
| "Analyze the Q3 sales numbers ... report the three biggest movers" | complex, Opus `high` ("fixes or hunts a defect") | Sonnet 5.5 for data analysis (matrix) |
| "Fix the typo in README.md line 3" | complex, Opus `high` | a trivial edit; no source puts it on Opus at `high` |
| A French brief | standard, Sonnet, reason "not in English" | not documented |

The word lists are software words (payments, schemas, migrations, auth), and "analyze" counts as a defect hunt in a call brief, so the level tracks vocabulary, not difficulty, once the work is not code.

### Which design gives the best quality at the lowest cost

- Start strong by default: "For most agent workloads, start with Claude Opus 5.5 at its default effort (`medium`)". https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence#compare-models-on-cost-per-task
- Go cheap only where the output is checkable: "High-volume work with outputs you can check: Try Claude Haiku 5.5 first", and when quality falls short, "If you lowered effort, restore it; otherwise try the next tier up at its default effort". https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence#start-here
- The measured saving comes from re-running failures, and it needs a real failure signal: "you need a failure signal (here, the benchmark's own tests); a checker that passes bad work lets those failures through." https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence#re-run-failures-at-higher-effort
- The bill is set by the hard tail: "The bill is decided by the tasks the cheaper model fails ... Price the tail of your workload, not the median". https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence#compare-models-on-cost-per-task
- Cheap subagents on coding did not beat lower effort: Haiku 5.5 subagents under Opus 5.5 "were an alternative to lowering effort, not better", cutting cost 32% and the pass rate about 4 points. Delegation "came out ahead in only two situations": routine work with a long cost tail, and work larger than one context window. https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence (the section on delegating bulk work)
- No source measures a model chosen from the brief's wording by a hook, and none measures the calling model's own per-call pick against a fixed mapping.

Read together: the sources back a fixed mapping by role in the agent definition, a strong default for everything else, the caller escalating when a check fails, and hard limits enforced by the harness. A classifier is allowed only where it is shown to classify accurately, which no source shows for brief wording.

### What a caller-named design with a cap and a floor needs from the plugin

- An explicit instruction to name effort, or Claude leaves it out by the tool's own text (type file, `Agent.effort`, quoted above). Session text must read as facts: "Text framed as out-of-band system commands can trigger Claude's prompt-injection defenses". https://code.claude.com/docs/en/hooks#add-context-for-claude
- The rules themselves, written down, since "Agents struggle to judge appropriate effort for different tasks" (research post above). A short table by kind of work, covering non-software work, is what the sources give (matrix, legal guide, model guide).
- Pass-through in the mod: "If an installed mod sets a model in its `agent.spawn` hook, Claude Code uses that model in place of the per-invocation parameter." https://code.claude.com/docs/en/sub-agents#choose-a-model. So the mod must hand on the caller's model and change it only to hold a cap or floor.
- A floor held by the plugin, since no native floor is documented, and a cap that clamps where the native `Agent(model:...)` rule only denies (permissions page above). `availableModels` and `maxEffortLevel` already cap natively (see `caller-levels-and-redo.md` Q1).
- Nothing extra for the cache: a subagent's "first request doesn't read the parent's cache, because the two prefixes differ". https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache

## Verdict

Partly right.

Keeping a model the caller names, and keeping an agent definition's own `model`, match the two choosers the docs name (sub-agents "Choose a model", the Agent tool's `model` text). Using English regex over the brief as the main source of the level does not: no source describes or measures it, the one source that allows a classifier requires that it "be handled accurately" and that added complexity "demonstrably improves outcomes", and on non-software briefs it sends a legal summary and a literature review to Haiku where the platform's legal guide and model guide point to Opus or above. The session text and the route skill also tell Claude not to name a level, the opposite of what the research system found it needs ("embedded scaling rules in the prompts").

## What the sources do not say

- Whether the calling model's own per-call pick beats a fixed mapping in definitions, in quality or cost. Not documented; no measurement either way.
- Any measurement of routing by the wording of a delegation brief, by regex or by a model. Not documented.
- How reliably Claude follows a plugin's session-start instruction to name `model` and `effort`. The docs say a plain instruction is followed "nearly every time" and give no rate for this case.
- Whether `tool.describe` can change the Agent tool's parameter text, as opposed to the tool's description. Not documented; the type file shows `description` only.
- A native floor on a subagent's model or effort. Not documented.
- Measured model choice for contract review, tax or other legal analysis beyond summarization, and for long-form writing. Not documented beyond the legal guide's summarization advice and the model guide's table, which gives no numbers.
- Model choice for a brief in another language. Not documented.
- What the right default is for a call that names nothing in a session on Sonnet or Haiku. The docs describe inheriting the parent's model and say most workloads start on Opus 5.5; they do not say a plugin should lift an inherited model.
- The research system's scaling rules are from June 2025 on Claude 4 models. Whether the same rules hold on the 5.5 models is not documented.
