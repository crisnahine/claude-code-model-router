# Model health: routing around a model that fails

2026-11-25: this note checks Model Router as it stood on 2026-11-24, before the 0.2.0 redesign. "What we built" describes that code, and some of what it names is gone or works differently now. What the code does now is in the [architecture review](../architecture-review.md).

## What we built

- `hooks.agent_failed` runs on `PostToolUseFailure` for `Agent|Task`. It passes the `error` string and `is_interrupt` to `calls._failed`, which asks `health.is_model_error`. That function is one English regex, `MODEL_ERROR`: the word "model" followed within 80 characters by phrases such as "not found", "unavailable", "invalid", "permission", or the tokens `not_found_error`, `model_not_found`, "unknown model".
- `health.failed` counts strikes per model in `state.json` under `health`. Two strikes (one for a full ID the mod sent) call `_route_around`, which sets `unavailable_until` 1, then 3, then 7 days out (`OUTAGE_DAYS`), growing with each outage.
- `health.ran` reads `resolvedModel` from `post_agent`. A run on the asked family clears the record. A run on another family counts as a substitution, and two of them route the model around too. A run with `modelsUsed` set, under the force setting, or on the untouched model is ignored.
- `health.refused`, called from `fallback._guard`, counts a strike when a fallback rewrite came back without having run and the model has never run here.
- `Registry.available` drops unhealthy models (keeping all if none is left), and `Registry.clamp` picks the closest usable model that is not stronger, else the weakest. `router.py` applies the clamp to every target, a caller's named model included. `Registry.newest_id` skips a full ID that failed, so the alias runs.
- `hooks.agent_failed` then tells Claude to re-issue the call with the clamped model. `report.models_data` shows `routed_around` rows, and `cli` can `forget` the record.

## What the sources say

What Claude Code does on its own when a model can't be used:

- Fallback chains exist and cover subagents. "When the primary model is overloaded, unavailable, or returns another non-retryable server error, Claude Code can switch to a fallback model instead of failing the request. Authentication, billing, rate-limit, request-size, and transport errors ... never trigger a switch." Set with `--fallback-model sonnet,haiku` or the `fallbackModel` array setting. "The switch lasts for the current turn only, so your next message tries the primary model first again." "Claude Code also applies the chain to subagents ... the subagent continues on the model that accepts the request." https://code.claude.com/docs/en/model-config.md (section "Fallback model chains")
- The setting is documented: "`fallbackModel`: Name backup models for Claude Code to try, in order, when your primary model is overloaded or unavailable ... Without a chain, Claude Code retries the same model and then surfaces the server's error, and you retry or switch models yourself." https://code.claude.com/docs/en/settings-reference.md (section "fallbackModel")
- "Claude Code doesn't confirm the chain at startup and `/status` doesn't display it." https://code.claude.com/docs/en/model-config.md (section "Fallback model chains")
- Changelog 2.1.247: "Fixed sub-agents dying on a first-call model 404: they now use the session's fallback model chain, and the error returned to the parent includes the error type, status, request id, and model". Changelog 2.1.330: "Changed a subagent's model fallback to carry over: agents with no model and forks it then starts run on the fallback". https://code.claude.com/docs/en/changelog
- A subagent that switched says so: "If a subagent's report opens with the following line, the subagent finished on a fallback model: `⚠ This agent switched to <model> because its earlier model could not be used.`" https://code.claude.com/docs/en/sub-agents.md (section "API errors in subagents")
- Allowlist blocks don't fail a subagent: "Claude Code runs the subagent or teammate on a fallback model rather than failing the request." https://code.claude.com/docs/en/model-config.md (section "Restrict model selection"). The order is: the newest permitted version of a blocked family alias, then `CLAUDE_CODE_SUBAGENT_MODEL`, then "The main conversation's model, or the spawning subagent's model for a nested subagent". https://code.claude.com/docs/en/sub-agents.md (section "When an allowlist blocks a subagent model")
- Enterprise org restrictions substitute too: "A notice prefixed with an agent, skill, or command name means the restriction applied to that subagent's requested model: the subagent runs on the substituted model". https://code.claude.com/docs/en/errors.md (section "Model is restricted by your organization's settings"). "Haiku models are always available and can't be disabled" and "An access change takes effect on new requests within about a minute". https://code.claude.com/docs/en/model-config.md (section "Organization model restrictions")
- Bedrock and Agent Platform: "When Amazon Bedrock rejects your session's model as unavailable to your account, Claude Code switches your session to another model". Without a chain the request fails when "Your session is on a pinned model, a specific version you picked". https://code.claude.com/docs/en/amazon-bedrock.md (section "When a model is disabled mid-session"), same wording for Agent Platform at https://code.claude.com/docs/en/google-vertex-ai.md. The startup checks "remember on this machine which models they found your account can't invoke, for up to a day", and "Once ten minutes have passed since the last check, Claude Code checks a remembered refusal of a current default model again at launch." https://code.claude.com/docs/en/amazon-bedrock.md (section "Startup model checks"), https://code.claude.com/docs/en/env-vars.md (`CLAUDE_CODE_SKIP_MODEL_ACCESS_MEMORY`)
- Content-classifier fallback is separate. A flagged subagent request "re-runs on the fallback model" under "Switch automatically", or under "Ask each time" "the subagent fails with `Agent terminated early due to an API error` and the refusal message". https://code.claude.com/docs/en/model-config.md (section "Subagents switch or fail without asking")

The errors that name a model, as Claude Code documents them (https://code.claude.com/docs/en/errors.md):

- "There's an issue with the selected model (claude-...). It may not exist or you may not have access to it." (section "There's an issue with the selected model")
- "Model 'claude-opus-9' not found" (section "Model not found")
- "Model '<name>' is not available. Your organization restricts model selection." (section "Model is restricted by your organization's settings")
- "API Error: 400 Claude Code 2.1.219 does not support this model; version 2.1.255 or newer is required." with "the error code `claude_code_version_too_old`" (section "Claude Code does not support this model")
- "Claude Opus is not available with the Claude Pro plan." (section "Claude Opus is not available with the Claude Pro plan")
- For a subagent: "A subagent's API request failed terminally, for example because a usage limit was reached or retries for a server error ran out ... `Agent terminated early due to an API error: <error detail>`" (section "Agent terminated early due to an API error")
- On the API, "404 - `not_found_error`: The requested resource was not found", "403 - `permission_error`", "529 - `overloaded_error`". The page advises: "Catch the SDK's typed classes rather than string-matching error messages". https://platform.claude.com/docs/en/api/errors. Changelog 2.1.265: "model access failures return 404". https://code.claude.com/docs/en/changelog

What a hook can see:

- `PostToolUseFailure` "Runs when a tool that started executing fails". Its `error` is a "String describing what went wrong. The format depends on the tool that failed", and the page says: "Key your hook on `tool_name`, `is_interrupt`, and the `Exit code N` first line; treat the rest of the string as display text, not a stable format." https://code.claude.com/docs/en/hooks.md (section "PostToolUseFailure input")
- A background subagent's failure doesn't come back on the Agent call: the tool returns at launch with `status: "async_launched"`, and later "the subagent is marked failed, and the message Claude receives when it ends names the API error". https://code.claude.com/docs/en/hooks.md (section "Agent"), https://code.claude.com/docs/en/sub-agents.md (section "API errors in subagents")
- A classified error exists only on `StopFailure`, which "Runs instead of Stop when the turn ends due to an API error", with `error` one of `rate_limit`, `authentication_failed`, ..., `invalid_request`, `model_not_found`, `server_error`, ... "For an HTTP `529` overloaded response, the value is `server_error`". It is listed as a per-turn event. https://code.claude.com/docs/en/hooks.md (section "StopFailure")
- The mods type file (generated by Claude Code 2.1.330 in `plugins/model-router/.claude-plugin/types/claude-code/index.d.ts` of the main checkout) gives `turn.complete` a `reason` of `'answer' | 'aborted' | 'refusal' | 'error'` with `agentId` for a subagent's run, but no error kind. The kind (`ModelApiError`: "`rate_limit`, `overloaded` and `server_error` may clear on their own; `authentication_failed`, `billing_error`, `invalid_request`, `model_not_found` will not") is typed only on `$.model.complete` and `$.model.fork` results and on `StopFailure`. `agent.report` has `status: 'completed' | 'failed' | 'stopped'` and text only.
- `resolvedModel` is "Model the subagent started on, which may differ from the requested model", "such as when `availableModels` or another override applies", and `modelsUsed` is "set only when the model was swapped mid-run". https://code.claude.com/docs/en/hooks.md (section "Agent")
- A fallback rewrite can be denied for reasons that have nothing to do with the model: "When your hook returns `updatedInput` with no `permissionDecision` in auto mode, Claude Code can deny the changed call. The server reviewed the input Claude wrote, not the input your hook returned." https://code.claude.com/docs/en/hooks.md (section "PreToolUse updatedInput in auto mode")

A check of `MODEL_ERROR` against the documented strings above (the regex copied into a scratch script, nothing in the repo run): it misses "There's an issue with the selected model ... may not exist or you may not have access to it", "does not support this model", "Claude Opus is not available with the Claude Pro plan" and the Bedrock "Switched to <fallback> because <model> is not available". It matches "Model '...' not found" and the org-restriction wording. It also matches unrelated text such as "model User is invalid".

## Verdict

Partly right. Claude Code already handles most of this: a configured `fallbackModel` chain moves a subagent off an unavailable model (first-call 404s included since 2.1.247), allowlist and org restrictions substitute instead of failing, and Bedrock and Agent Platform switch an alias session by themselves. Memory across turns is the one thing it does not give a subagent, since the chain lasts one turn. The plugin also creates a risk of its own when the mod sends a full newest ID, and no source covers that risk. So a small memory of models that failed is defensible. But the detector parses English that the hooks page calls "display text, not a stable format", and it misses the main documented message. It also strikes a model for an auto-mode denial that the docs tie to the changed input. On top of that, it locks a model out for up to 7 days, against Claude Code's own "up to a day" with a ten-minute recheck, and its stand-in steps down where Claude Code's own order steps to the parent's model.

## What to change

1. Stop parsing English phrases in the failure text. Replace `MODEL_ERROR` with a match on the API's error type identifiers that the error carries (`not_found_error`, `permission_error`, `model_not_found`, `claude_code_version_too_old`) and never strike on `overloaded_error`, `rate_limit` or 5xx. Touches `health.MODEL_ERROR`, `health.is_model_error` and `calls._failed`, and deletes the phrase list. Backed by https://code.claude.com/docs/en/hooks.md ("treat the rest of the string as display text"), changelog 2.1.247 (the error "includes the error type, status, request id, and model") and https://platform.claude.com/docs/en/api/errors. Dropping the phrase parse is required by a source. The token list that replaces it is judgment, since the detail's layout is not documented.
2. Stop counting a refused fallback rewrite as a model failure. Delete `health.refused`, `REFUSED`, and the `health.refused(decision["repeat_of"])` call in `fallback._guard`. Keep the guard's pass-through. Backed by https://code.claude.com/docs/en/hooks.md (section "PreToolUse updatedInput in auto mode"), which puts the denial on the changed input, not the model. Required by a source.
3. Shorten the lockout to one window of at most a day, with no growth. Delete `OUTAGE_DAYS`, the `outages` counter and `_outage_days`, and keep one `unavailable_until`. Touches `health._route_around`, `health.healthy`, `health.ran` and the clock clamp in `Health.healthy`/`settle`. Backed by https://code.claude.com/docs/en/amazon-bedrock.md ("for up to a day", rechecked after ten minutes) and https://code.claude.com/docs/en/model-config.md (org changes take effect "within about a minute"). Judgment: no source sets a number for a plugin.
4. When a model is routed around, stop stepping down to a weaker stand-in. Either leave the call's `model` unset so Claude Code's documented order applies (definition, `CLAUDE_CODE_SUBAGENT_MODEL`, the parent's model), or take the next stronger usable model inside the cap. Also never replace a model the caller named. Touches `Registry.clamp`/`Registry.available` as `router.py` uses them for the final target, and the `hooks.agent_failed` note. Backed by https://code.claude.com/docs/en/sub-agents.md (section "When an allowlist blocks a subagent model") and the goal that output quality ranks above cost. Judgment.
5. Tell users that `fallbackModel` (or `--fallback-model`) is the first fix for an unavailable model, and that the router's health record only adds memory across turns. This goes in the docs, not a session note, so it costs no tokens. Touches `docs/CLAUDE_CODE_DOCS.md` (a row under "Model limits, providers and prices") and the README's model section. Backed by https://code.claude.com/docs/en/settings-reference.md (section "fallbackModel") and https://code.claude.com/docs/en/model-config.md ("doesn't confirm the chain at startup"). Judgment.
6. Write down the coverage gap. Health hears only foreground `Agent` calls: a background subagent's failure arrives after the call returned `async_launched`, and workflow stages never pass through the Agent tool. Add this to "Where it goes past the docs" in `docs/CLAUDE_CODE_DOCS.md`. Backed by https://code.claude.com/docs/en/hooks.md (section "Agent") and https://code.claude.com/docs/en/sub-agents.md (section "API errors in subagents"). Judgment.

## What the sources do not say

- That `PostToolUseFailure` fires for an Agent call that ends in "Agent terminated early due to an API error". The hooks page says the event runs when a tool "threw an error". That this case counts is implied, not documented.
- The layout of the error detail after that prefix. The changelog lists what it includes, not its order or spelling.
- Whether `StopFailure` fires when a subagent's own turn ends on an API error. Not documented. The page lists it as a per-turn event of the session.
- What happens when a subagent on a full model ID is refused on Bedrock or Agent Platform with no chain. The pages cover the session's model only.
- Whether a `fallbackModel` chain applies to workflow agents and teammates. The page names subagents and compaction.
- How long a plugin should remember a failed model, and whether a plugin should keep such memory at all. Not documented.
- Whether `resolvedModel` names the chain's model or the asked model after a first-call fallback. The field is "Model the subagent started on". Which one that is after a first-call 404 is not documented.
