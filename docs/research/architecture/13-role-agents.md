# The seven role agents

2026-11-25: this note checks Model Router as it stood on 2026-11-24, before the 0.3.0 redesign. "What we built" describes that code, and some of what it names is gone or works differently now. What the code does now is in the [architecture review](../architecture-review.md).

Checked 2026-11-24 against Claude Code 2.1.331 (`claude --version`), with every page fetched the same day as `.md`. Code read in the `redo-fixes` worktree. The mod type files are not in that worktree, so the copy in the main checkout (`plugins/model-router/.claude-plugin/types/`, headed "Written by Claude Code 2.1.330") is the one cited as `[mod-types]`.

## What we built

- `plugins/model-router/agents/` ships seven agents. `scout`, `verifier` and `docs-researcher` pin `model: haiku` and `effort: medium`; `scout` and `docs-researcher` also set `omitClaudeMd: true`. `architect`, `reviewer`, `implementer` and `deep-solver` carry no `model` or `effort`, so the router routes them by brief.
- Tools: `scout` and `reviewer` get `Read, Grep, Glob`; `architect` gets those plus `Bash, WebFetch`; `verifier` gets `Read, Grep, Glob, Bash`; `docs-researcher` gets `Read, Grep, Glob, WebFetch, WebSearch`; `implementer` and `deep-solver` inherit every tool.
- `profile.py` `ROLES` gives `model-router:architect` and `model-router:reviewer` a `complex` floor and `model-router:deep-solver` a `hardest` floor, all three `strong` (start no lower than the request's level, used in `spawn.facts`). `role()` also reads any other agent's name: `_HEAVY_NAME` (architect, review, audit, security, debug, design, plann, solver) gets a `complex` floor, `_LIGHT_NAME` (explore, search, scout, find, fetch, summar, format, lint, runner, verif, grep) a `standard` cap. Names ending in `verifier` or `reviewer` are checkers (`gates.is_checker`).
- `config/models.json` `crew` lists the seven; `test_crew_matches_agent_files` and `test_only_the_always_cheap_role_agents_carry_a_model` hold the frontmatter to it.
- Users: `skills/ship/SKILL.md` runs scout, architect, deep-solver, implementer, verifier and reviewer as a pipeline; `skills/refresh/SKILL.md` runs `docs-researcher`; `gates.strong_agent`, `gates.finished_check` and `gates.unverified_edit` name architect, deep-solver, reviewer and verifier in Stop reasons.
- `router.decide` keeps a pinned agent's model (`agent_pins: respect`), sets effort when nobody chose it (`_effort_decided`), and routes the built-ins Explore, Plan and general-purpose by brief (`agents.BUILTIN`).

## What the sources say

Plugin-shipped agents: fields, limits, names

- Supported fields: "`name`, `description`, `model`, `effort`, `maxTurns`, `autoCompactWindow`, `tools`, `disallowedTools`, `skills`, `memory`, `background`, `omitClaudeMd`, `isolation`, `color`, and the `cacheTtl` key of `experimental`." Ignored: "`permissionMode`, `hooks`, `mcpServers`, and `initialPrompt`." https://code.claude.com/docs/en/plugins/components (Frontmatter fields in plugin agents). Every field our seven use is on the supported list.
- `model` takes "`sonnet`, `opus`, `haiku`, `fable`, a full model ID such as `claude-opus-5-5`, or `inherit`. When you omit it, Claude Code picks the model in the subagent model order." `effort` "Overrides the session effort level, but not the `CLAUDE_CODE_EFFORT_LEVEL` environment variable." https://code.claude.com/docs/en/sub-agents (Frontmatter reference)
- Model order: the per-invocation `model` parameter, then "The `model` field in the subagent's definition, including `inherit`", then `CLAUDE_CODE_SUBAGENT_MODEL`, then the parent's model. A mod's `agent.spawn` model is used "in place of the per-invocation parameter". https://code.claude.com/docs/en/sub-agents#choose-a-model
- Effort: "To run a subagent at its own effort level, set the `effort` field in its definition. When you ask Claude to run a non-fork subagent at a specific effort level, it can also pass an `effort` parameter for that invocation. The parameter overrides the `effort` field." https://code.claude.com/docs/en/sub-agents#choose-an-effort-level. The tool's own text: "Set this ONLY when the user, or instructions such as CLAUDE.md or a skill, explicitly ask that this agent or delegated work run at a specific effort level, never on your own judgment" `[mod-types]` (`claude-code-tools`, `Agent.effort`).
- Scope: a plugin's `agents/` directory is priority "5 (lowest)", and a plugin agent is named `<plugin>:<name>`. https://code.claude.com/docs/en/sub-agents#choose-the-subagent-scope, https://code.claude.com/docs/en/plugins/components (Agents)
- Tools: "Inherits every tool available to subagents if omitted." A `Read, Grep, Glob, Bash` agent "has no Edit, Write, or MCP tools but can still change files through Bash." https://code.claude.com/docs/en/sub-agents (Frontmatter reference; Restrict which tools a subagent can use). Background runs, the default, keep `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`, `WebFetch`, `WebSearch` among others. https://code.claude.com/docs/en/sub-agents#available-tools
- Description budget: "When the combined descriptions of your subagents, except the built-in ones, exceed 15,000 tokens, Claude Code shows a warning at startup." https://code.claude.com/docs/en/sub-agents
- Teammates and workflows reuse definitions: a teammate can use a type "from the project, user, managed, or plugin subagent scope", and Claude Code applies its `tools`, `model`, and for an in-process teammate its `effort`. https://code.claude.com/docs/en/agent-teams#use-subagent-definitions-for-teammates

The built-in agents

- Explore: "A fast, read-only agent optimized for searching and analyzing codebases." Model: "the parent conversation's model. When the parent conversation runs Fable, Explore runs on Opus or stays on Fable, based on how you connect." "Claude delegates to Explore when it needs to search or understand a codebase without making changes." "Claude specifies a thoroughness level: quick ..., medium ..., or very thorough." https://code.claude.com/docs/en/sub-agents#built-in-subagents
- Changing Explore's model: "A user or project subagent named `Explore` overrides the built-in and keeps its own `model` field, so define one with `model: haiku` to run exploration on a lower-cost model." And "Setting `CLAUDE_CODE_SUBAGENT_MODEL` by itself doesn't change the model the built-in Explore and Plan subagents run on." Same page.
- Plan: "A research agent used during plan mode to gather context before presenting a plan", read-only, inherits the parent's model. Same page.
- General-purpose: "A capable agent for complex, multi-step tasks that require both exploration and action", every tool, the parent's model; "Purpose: complex research, multi-step operations, code modifications". Same page.
- Others: `claude` is the catch-all "When a task doesn't fit a more specialized agent"; `claude-code-guide` runs on Haiku "When you ask questions about Claude Code features". Same page.
- "Explore and Plan start without your CLAUDE.md files and the git status snapshot to keep research fast and inexpensive." Same page. Our `omitClaudeMd` on scout copies that ("Added `omitClaudeMd` to agent frontmatter ... letting custom and plugin subagents run without user, project and local CLAUDE.md files", https://code.claude.com/docs/en/changelog, 2.1.271).
- History of Explore's model: 2.1.198 "The built-in Explore agent now inherits the main session's model (capped at opus) instead of running on haiku". https://code.claude.com/docs/en/changelog

How Claude picks an agent

- "Claude automatically delegates tasks based on the task description in your request, the `description` field in subagent configurations, and current context. To encourage proactive delegation, include phrases like 'use proactively'." https://code.claude.com/docs/en/sub-agents#understand-automatic-delegation
- "Write descriptions that single out one subagent: Claude uses the description to decide when to delegate. Make each description specific enough to route to the right subagent." "Design focused subagents: each subagent should excel at one specific task." https://code.claude.com/docs/en/sub-agents (Example subagents, best practices)
- "Define a custom subagent when you keep spawning the same kind of worker with the same instructions." https://code.claude.com/docs/en/sub-agents
- "Broad codebase searches go to the built-in Explore agent." https://code.claude.com/docs/en/best-practices#know-what-subagents-cost
- A plugin can measure delegation: "`claude plugin eval` runs each prompt with and without the plugin and scores the results." https://code.claude.com/docs/en/sub-agents#understand-automatic-delegation

What a role agent adds

- "And by default it's the same model (or a smaller one) on the same task. You get parallelism or a fresh pair of eyes out of it, but not a smarter answer." https://code.claude.com/docs/en/best-practices#know-what-subagents-cost
- "Delegate to a subagent for a better answer" is listed as old advice: "Handing the same task to a subagent doesn't make the answer any better. A fresh reviewer does help, because it hasn't seen your reasoning." https://code.claude.com/docs/en/best-practices (What you can stop doing)
- Subagents pay off for parallel work, long output, "Getting a reviewer that hasn't seen how the code was written", and "Giving a task fewer tools than the main session has". "Give a custom subagent ... only `tools: Read, Grep, Glob`. Now it's a reviewer that can't edit anything, and that limit is enforced by Claude Code rather than requested in a prompt." Same page.
- "Set `model: haiku` in a subagent's definition if its work is simple, like collecting the files that import a module or checking links in the docs." Same page. "For simple subagent tasks, specify `model: haiku` in your subagent configuration." https://code.claude.com/docs/en/costs
- Haiku subagents under Opus on coding "were an alternative to lowering effort, not better", cutting cost per attempt 32% and the pass rate about 4 points. https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence (the section on delegating work to subagents)

Skills as the other home for a fixed brief

- "Add `context: fork` to your frontmatter when you want a skill to run in isolation. Claude Code starts a new subagent of the type set in the `agent` field and gives it the skill content as its prompt." With `context: fork`, `model` and `effort` set "the forked subagent's" model and effort. https://code.claude.com/docs/en/skills (Run skills in a subagent; Frontmatter reference)

Work that is not code

- The docs' own examples include one: "A domain-specific subagent for data analysis work. It explicitly sets `model: sonnet` for more capable analysis." https://code.claude.com/docs/en/sub-agents (Example subagents, Data scientist)
- General-purpose and `claude` are the built-ins with no code-only purpose; Explore and Plan are described in codebase terms. https://code.claude.com/docs/en/sub-agents#built-in-subagents

## Verdict

Partly right. The files follow the plugin-agent rules exactly: every field is supported, the read-only reviewer is the shape the best-practices page recommends, and `model: haiku` on simple roles is the documented cost lever, so verifier and reviewer and the Haiku pins are right. But scout overlaps Explore and docs-researcher overlaps `claude-code-guide`, which works against "write descriptions that single out one subagent", and deep-solver adds only a stronger model, which the docs say delegation alone doesn't give and which a per-call `model` and `effort` named by the skill already does. The name-based floors and caps in `profile.py` have no documented basis: the docs control a subagent's level only through its own `model` and `effort` fields or the call's parameters, and they read an agent's name only as its identity. Most roles are written for code, so for other work Claude falls back to general-purpose.

## What the sources do not say

- Whether a per-call `model`, or a mod's `agent.spawn` model, changes the model of the built-in Explore or Plan. The docs name only a same-named user or project definition and `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`. Not documented; item 1 depends on it.
- Whether a plugin agent named `Explore` overrides the built-in. The docs say "A user or project subagent". Not documented for plugins, and the scoped name suggests it doesn't.
- How Claude chooses between a plugin agent and a built-in whose descriptions overlap, beyond "the task description in your request, the `description` field ..., and current context". Not documented.
- Which tools `claude-code-guide` has, and whether it reads the changelog. Not documented.
- A floor in frontmatter. `model` and `effort` are exact values; "at least this model" is not documented anywhere.
- Whether a definition's `effort` reaches a split-pane teammate. The teams page lists it for in-process teammates only.
- Any measurement of a role-specialized subagent against general-purpose with the same model and brief. The only delegation numbers are on model mixes, not on role prompts.
- Whether a forked skill's subagent fires `agent.spawn`. Not documented; the repo's own live run on 2.1.330 saw none (`docs/research/model-control.md`).
- Guidance on custom subagents for writing, research or other work outside code, beyond the one data analysis example.
