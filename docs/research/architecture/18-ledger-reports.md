# The usage ledger and the cost reports

2026-11-25: this note checks Model Router as it stood on 2026-11-24, before the 0.3.0 redesign. "What we built" describes that code, and some of what it names is gone or works differently now. What the code does now is in the [architecture review](../architecture-review.md).

Researched 2026-11-24 on Claude Code 2.1.331 (`claude --version`). Every docs page was fetched the same day as `.md`. The mods type file used is `plugins/model-router/.claude-plugin/types/claude-code/index.d.ts`, headed "Written by Claude Code 2.1.330" and "EARLY ACCESS: this surface may change between releases without notice". It sits in the main checkout; the `redo-fixes` worktree has no `types/` folder. It is cited below as `[mod-types]`.

## What we built

- `ledger.py` appends one JSON line per event to `${CLAUDE_PLUGIN_DATA}/ledger.jsonl` through `store.append_ledger`, which halves the file once it passes 4 MiB (`store.LEDGER_MAX_BYTES`). Nothing removes rows by age.
- Row kinds: `spawn` (`ledger.spawn`: agent, level, signals, model, was, effort, reason, `escalated_from`, `held`, and the first 120 characters of the Agent call's `description`), `result` (`ledger.result`: `resolvedModel`, status, `totalTokens`, `modelsUsed`), `model_error`, `turn` (main-loop effort raises) and `usage` (`ledger.usage`).
- `usage` rows come from the mod. `hooks/router.ts` keeps every `turn.step` `result.usage` in `turnRequests`, and on each `turn.complete` (main loop and every subagent turn) runs the Python runtime through `$.process.run` with `mod-usage`. `mod.usage` then calls `ledger.usage`, which prices the turn with `ledger.turn_cost`.
- `ledger.turn_cost` prices each request on its own model through `Registry.cost` and `Registry.price`, using the `prices` block in `config/models.json`: Anthropic API list prices, a `-*` family fallback, a one-hour cache write split, and Haiku 5.5's `long_prompt` rates over 100K. `config._prices` lets the user's own `~/.claude/model-router.json` add or change prices.
- `report.usage_data` and `report.usage` build `/model-router:usage`: calls and levels per agent, the model each ran on, `totalTokens` per model, and a "Spend at list price" table split into main and subagent loops, with an "unpriced" note. `report._held_back` reads `held` from the last 7 days of spawn rows. `bench/run.py` reads `usage` rows for spend by agent type and `spawn` rows for the routed levels.

## What the sources say

What Claude Code records and shows itself

- `/usage` (with `/cost` and `/stats` as aliases) "Show session cost, plan usage limits, and activity stats" https://code.claude.com/docs/en/commands. Its Session block prints an `Estimated cost` line and "Usage by model" with input, output, cache read and cache write per model, and "Claude Code computes the dollar figure locally from token counts at list price, unless a `modelPricing` table is in effect" https://code.claude.com/docs/en/costs#using-the-usage-command.
- On a plan, `/usage` also shows "recent usage attributed to skills, subagents, plugins, and individual MCP servers, each shown as a percentage of the total" for the last 24 hours or 7 days, "computed from local session history on this machine" https://code.claude.com/docs/en/costs#plan-usage-breakdown. The plugin docs say the same: "the `/usage` breakdown attributes recent usage to skills, subagents, plugins, and MCP servers as a share of the total" https://code.claude.com/docs/en/plugins/measure.
- The status line gets `cost.total_cost_usd`, "Estimated session cost in USD, computed client-side at list price unless a `modelPricing` table is in effect. May differ from your actual bill" https://code.claude.com/docs/en/statusline.
- `claude -p --output-format json`: "the response payload includes `total_cost_usd` and a per-model cost breakdown ... Both figures are client-side estimates" https://code.claude.com/docs/en/headless. `modelUsage` covers "the main loop, subagents, and internal calls such as compaction and Workflow agents" https://code.claude.com/docs/en/agent-sdk/typescript. Each entry's `costBasis` says "`list` for list price, `managed` for a `modelPricing` table, or `unknown`" https://code.claude.com/docs/en/agent-sdk/cost-tracking.
- OpenTelemetry: the cost counter is "Incremented after each API request" and carries `model`, `query_source` (`main`, `subagent`, `auxiliary`, `plugin_model_complete`, `plugin_model_classify`), `speed` ("`fast` when the request used fast mode"), `effort`, `agent.name` and `plugin.name` https://code.claude.com/docs/en/monitoring-usage. The `api_request` event has `cost_usd`, the token counts and `cache_creation_5m_tokens` / `cache_creation_1h_tokens` (same page). For third-party plugins "`plugin.name` is `third-party`" and custom agent names are "replaced with `custom`" unless `OTEL_LOG_TOOL_DETAILS=1` https://code.claude.com/docs/en/plugins/measure.
- A plugin can't read that export: "Claude Code doesn't pass `OTEL_*` environment variables to the subprocesses it spawns, including the Bash tool, hooks, MCP servers, and language servers" https://code.claude.com/docs/en/monitoring-usage.
- The Agent result: "for token and cost rollups across subagents, use the token and cost counters filtered to `query_source` `subagent`, since `totalTokens` and `usage` cover the final request only". `totalTokens` "isn't a total across the whole run", and a background launch "carries no usage fields" https://code.claude.com/docs/en/hooks. The `subagent_completed` event's `total_tokens` is "roughly the subagent's context size at completion. Not a sum across the run" https://code.claude.com/docs/en/monitoring-usage.
- `/tasks` names each subagent's model and effort https://code.claude.com/docs/en/sub-agents.
- Mods: `$.session.usage()` "returns `{ startedAt, context, rateLimits, cost }`" https://code.claude.com/docs/en/plugins/mods/reference, and `session.measure` fires "After each turn" (same page). `$.agent.list()` "returns this session's subagents and teammates" (same page). The type file adds per-agent figures that the pages don't list: `AgentInfo.usage` is "Its own requests' tokens, one entry a model that answered", counting "its steps and their retries, its compactions, summaries, advisor, web tools and settings hooks, and auto mode's billed classifier calls", and `AgentInfo.cost` is "What `/cost` was credited for the requests of `usage`", where "Fast mode, long prompts and search fees are in it, which the counts of `usage` do not tell" `[mod-types]`. Its limits: "a workflow's are not" in the list, and an entry stays only "until the engine drops its task" `[mod-types]`.
- `SessionCost` in `[mod-types]`: "A client-side estimate, priced locally at list price or the managed `modelPricing` rates ... On a subscription, usage inside the plan is not billed in dollars, so there the figure is no charge at all. Do not bill anyone or make a financial decision from it. A mod that shows it should label it an estimate." `rateLimits` "is empty off a subscription" `[mod-types]` (`SessionUsage`).
- Across days, Claude Code keeps `stats-cache.json`, "Aggregated token and cost counts shown by `/usage`" https://code.claude.com/docs/en/claude-directory. Its format is not documented. Transcripts carry request usage, but `transcript_path` "may lag the in-memory conversation" https://code.claude.com/docs/en/hooks, and the transcript format is not documented as stable (model-control.md Q3).

How accurate a plugin's own price list can be

- The prices in `config/models.json` match the Anthropic API table on 2026-11-24, including Opus 5.5 and Sonnet 5.5 cache reads at 0.05x and Fable 5.2 and 5.1 at 0.025x https://platform.claude.com/docs/en/about-claude/pricing. `upstream.py` does not fetch that page, so a price change is not flagged.
- Claude Code's own table has the same weakness and says so: the estimate can drift "when pricing changes", "the installed SDK version does not recognize a model", or "billing rules apply that the client cannot model" https://code.claude.com/docs/en/agent-sdk/cost-tracking.
- What a token-count price list can't see, from the sources:
  - Contracted rates. Claude Code reads `modelPricing`, which "changes what Claude Code reports, not what Anthropic charges", from managed settings only https://code.claude.com/docs/en/costs#report-spend-at-your-contracted-rates, https://code.claude.com/docs/en/settings-reference#modelpricing. The plugin ignores it.
  - Data residency. "Claude Code multiplies the list price of that response's tokens by 1.1" for responses at the data residency rate https://code.claude.com/docs/en/costs. `TurnUsage` has no field that says so `[mod-types]`.
  - Fast mode. It is premium pricing on Fable 5.2, Opus 5.5, Opus 5 and Opus 4.8 https://platform.claude.com/docs/en/about-claude/pricing. `TurnUsage` has no speed field `[mod-types]`; the OTel counters do (`speed`).
  - Search fees. "web search costs $10 USD per 1,000 searches, plus standard token costs" https://platform.claude.com/docs/en/about-claude/pricing.
  - Cloud providers. "For official pricing on Claude Models on Google Cloud (Google managed) and Amazon Bedrock, visit" their own pages, and "Regional and multi-region endpoints include a 10 percent premium over global endpoints" https://platform.claude.com/docs/en/about-claude/pricing. On those providers "spend controls live in your cloud provider's billing console" https://code.claude.com/docs/en/costs#cloud-providers.
  - Subscriptions. "Claude Pro, Max, and Ultra subscribers have usage included in their subscription, so the session cost figure isn't relevant for billing purposes" https://code.claude.com/docs/en/costs. On Team and Enterprise "Usage inside the seat allowance isn't metered in dollars" (same page).
- Cache writes: "`cacheCreation` type counts cache writes with the five-minute and one-hour cache lifetimes together" in the token counter https://code.claude.com/docs/en/monitoring-usage. A write that names no lifetime is priced as five minutes by `/cost` `[mod-types]` (`TurnUsage.ephemeral_5m_input_tokens`), which is what `Registry.cost` does.
- Haiku 5.5: "Each request is priced on its own: a request over the threshold pays the higher prices even when part of its prompt is a cache hit" https://platform.claude.com/docs/en/about-claude/pricing. `turn_cost` prices each request on its own; a turn with no requests list falls to the base rate.
- Coverage: a `turn.complete` usage is the turn's responses "summed" `[mod-types]`, while `AgentInfo.usage` also counts compactions, retries, advisor and hook requests `[mod-types]`. So the ledger's subagent tokens can be lower than what `/cost` counts for the same agent.

Storing prompts or descriptions on disk

- No page sets a rule for what a plugin may write about the user's work. Not documented.
- The plugin data folder is `~/.claude/plugins/data/<id>/`, "kept across plugin updates" and meant for "Installed dependencies such as `node_modules`, generated code, and caches". It is deleted "when you uninstall the plugin from the last place it's installed" https://code.claude.com/docs/en/plugins-reference.
- Claude Code's own session data: "These files are plaintext. Anything that passes through a tool is written to a transcript on disk", deleted after `cleanupPeriodDays`, 30 days by default https://code.claude.com/docs/en/claude-directory. The only plugin-data path in that sweep is `plugins/data/.set-aside/` (same page). `claude purge` deletes transcripts, auto memory, `tasks/`, `debug/`, `file-history/`, matching `history.jsonl` lines and the project entry in `~/.claude.json`, and nothing under `plugins/data/` (same page).
- Under the HIPAA configuration, "Securing and deleting that data is your organization's responsibility", and the page points admins at the Application data list https://code.claude.com/docs/en/hipaa-setup. That list doesn't name plugin data folders.
- Claude Code's own telemetry keeps prompt text out by default: `OTEL_LOG_USER_PROMPTS` "Enable logging of user prompt content (default: disabled)", and the user prompt event's `prompt` is "Redacted by default" https://code.claude.com/docs/en/monitoring-usage.
- The Agent call's `description` is "A short (3-5 word) description of the task" `[mod-types]` (`claude-code-tools` `Agent.description`), so the 120-character cut rarely trims. No plugin code reads the stored `description` back: `report.py` and `bench/run.py` read `agent`, `level`, `model`, `effort`, `escalated_from`, `held`, `cost_usd` and `agent_id`. The plugin's own docs already disclose the field (`docs/SECURITY.md`, `docs/FAQ.md`).

What Claude Code does not record

- No source has a field for the router's own facts: the level a call got, its signals, the reason, the model before routing (`was`), `escalated_from` or `held`. Claude Code can't hand these back, so a plugin that reports them has to keep them.

## Verdict

Partly right.

The routing rows (`spawn`, `result`, `model_error`, `turn`) are right to keep. They are the plugin's own decisions, which no Claude Code surface records, and `/model-router:usage`, `report._held_back` and the bench need them.

The dollar side is wrong to keep. It runs a second price table beside Claude Code's own estimate, and that table can't see `modelPricing`, the 1.1x data residency rate, fast mode, search fees or cloud provider prices (https://code.claude.com/docs/en/costs, https://platform.claude.com/docs/en/about-claude/pricing). It shows list-price dollars to subscribers, where "the figure is no charge at all" `[mod-types]`. Claude Code already gives a mod each agent's estimate, fast mode and search fees included (`AgentInfo.cost`), and the session total (`$.session.usage().cost`) `[mod-types]`, https://code.claude.com/docs/en/plugins/mods/reference.

The stored description text is never read back. It also sits outside the retention sweep and `claude purge` that Claude Code documents for its own session data (https://code.claude.com/docs/en/claude-directory).

## What to change

1. **Take dollars from Claude Code, not from a plugin price table.** In `hooks/router.ts` `turn.complete`, for a subagent turn, read the agent's entry from `$.agent.list()` and send its `cost` (`usd`, `hasUnknownPrice`) and `usage` (tokens per model) with `mod-usage`. `ledger.usage` stores those as given, and `report.usage_data` keeps the last row per `agent_id`, since the figures are running totals. Workflow agents aren't in `$.agent.list()` `[mod-types]`, so their rows keep tokens and no dollars. This deletes the `prices` block in `config/models.json`, `config._prices` and its merge, `Registry.prices`, `Registry.price`, `Registry.cost`, `ledger.turn_cost`, the `long_prompt` handling, `turnRequests` and the `turn.step` usage collection in `router.ts`, the "Add one under `prices`" note in `report.usage`, and the price and long-prompt tests. Backed by `[mod-types]` (`AgentInfo.cost`, `SessionCost`), https://code.claude.com/docs/en/costs and https://code.claude.com/docs/en/agent-sdk/cost-tracking. Judgment: no source requires it. The risk is that `AgentInfo.cost` is in the type file only, under "EARLY ACCESS". The smaller option is to drop dollars from the report altogether and point to `/usage`, which loses the bench's spend by agent type.
2. **Label every dollar figure as Claude Code's estimate, and say when it is no charge.** Change "Spend at list price" in `report.usage` and the text in `skills/usage/SKILL.md` to say the figure is Claude Code's estimate, not the bill. When the session is on a subscription (`$.session.usage().rateLimits` is non-empty `[mod-types]`), say that usage inside the plan is not billed in dollars. Deletes the "list prices from the registry" wording in `SKILL.md`. Required by a source: `SessionCost` says "A mod that shows it should label it an estimate" and that on a subscription "the figure is no charge at all" `[mod-types]`. Same idea in https://code.claude.com/docs/en/costs.
3. **Stop writing main-loop usage rows.** In `router.ts` `turn.complete`, skip `mod-usage` when `e.agentId` is undefined, and drop the `main` loop from `report.usage_data` spend. That removes one Python process per main-loop turn. `/usage`, the status line and `$.session.usage()` already show the session's cost and tokens by model (https://code.claude.com/docs/en/costs, https://code.claude.com/docs/en/statusline), and the router never picks the main loop's model. The `turn` rows for effort raises stay. Judgment, backed by those pages and by the per-process hook cost in `docs/research/caller-levels-and-redo.md` Q4.
4. **Stop storing the description text.** Remove `description` from `ledger.spawn` rows and from its callers (`spawn.py`), and update `docs/SECURITY.md` and `docs/FAQ.md`. No plugin code reads it back. Judgment: the sources don't set a rule for plugins. Backed by how Claude Code treats its own text: prompts redacted from telemetry by default (https://code.claude.com/docs/en/monitoring-usage), and session text swept after `cleanupPeriodDays` and cleared by `claude purge`, neither of which reaches the plugin data folder (https://code.claude.com/docs/en/claude-directory). `calls.py` also keeps the description as a key (`_TASK + task`) in the routes state for redo matching. That belongs to the redo decision, and the same reasoning would hash it the way `calls.identify` hashes the prompt.
5. **Drop ledger rows older than 30 days.** In `store.append_ledger`, when it trims, also drop rows whose `ts` is older than 30 days, Claude Code's default `cleanupPeriodDays`, and say in `docs/SECURITY.md` that `claude purge` and the retention sweep don't reach the plugin's data folder and uninstall does. Deletes nothing. Judgment, backed by https://code.claude.com/docs/en/claude-directory and https://code.claude.com/docs/en/settings-reference#cleanupperioddays. The smaller option is the docs line alone.
6. **Drop the final-request token column.** Remove `total_tokens` from `ledger.result` rows and the "Final-request tokens" column from `report.usage`. Per-agent tokens then come from item 1. The docs say `totalTokens` covers "the final request only" and to use the counters for rollups (https://code.claude.com/docs/en/hooks), and the OTel docs call the same figure "roughly the subagent's context size at completion" (https://code.claude.com/docs/en/monitoring-usage). Judgment.

## What the sources do not say

- Whether a plugin may store a user's prompt or task text on disk, or for how long. Not documented.
- The fields `AgentInfo.usage` and `AgentInfo.cost` are in the type file only, not on the mods pages. Whether they stay is not documented, and the type file is marked "EARLY ACCESS".
- Whether a workflow agent's cost can be read per agent from a mod. `$.agent.list()` leaves workflow agents out `[mod-types]`, and no other per-agent source for them is documented.
- How long a finished subagent stays in `$.agent.list()`. "a subagent's later" than seconds `[mod-types]` is all it says, so reading it at that agent's `turn.complete` is the only timing the sources support.
- The format of `stats-cache.json` and of transcript usage entries. Not documented, so neither is a safe read for a plugin.
- Whether Claude Code's estimate uses provider prices on Bedrock, Google Cloud or Foundry. The docs say "list price" unless `modelPricing` is set (https://code.claude.com/docs/en/costs). Which list is not documented.
- Whether `/usage`'s per-subagent and per-plugin share can be read by a plugin. Not documented. It is a screen only.
- Whether `cleanupPeriodDays` is meant to bind plugin data. Not documented. The sweep list doesn't include it.
